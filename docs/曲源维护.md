# 联网曲谱来源维护

## 当前来源与能力

| source | 入口 | 自动下载 | 说明 |
|---|---|---|---|
| `shallow` | https://delta-test.shallow.ink/harmonica | 否 | 匿名公开目录，完整分页；谱面需到原站查看 |
| `visualizer` | https://github.com/ChiZhou6/harmonica-visualizer/tree/main/songs | 是 | GitHub 文本谱；下载、内容 SHA、解析和音高/时值往返校验后保存 |
| `je` | https://github.com/zytx121/je | 否 | 通过 issue 标题搜索歌名；不少谱没有严格节奏，只提供原谱链接 |

不是所有搜索结果都可以直接演奏；`可下载` 与 `原谱链接` 会分别标注。JE 不静默补成等长音符。
上游文本谱的下载兼容性验证不等于人工确认每首曲子的旋律或节奏正确。

## 已移除的旧来源

- **jiko 在线抓取**：原 `community-songs.js` 当前返回 HTTP 200，但正文是访问限制提示及一首占位音阶，
  不是原曲库。旧版错误地将其标成可下载曲谱。已移除自动请求；旧参数会明确提示原因。
  不修改请求头来规避限制、不寻找受限接口的替代抓取路径。本地曲谱和简谱 DSL 支持保留。
- **shushu 旧 SSR 目录适配器**：本次仅取到首屏 60 条，ID 全部包含在 shallow 完整目录中。
  因重复且容易漏曲移除，**不代表 shushu 网站已失效**。
- 原 `--jiko-search` 参数保留为 `--song-search` 的历史别名，不再表示请求 jiko。
- `--source jiko`、`--source shushu` 保留退役提示，不再发起旧站请求。
- 不删除、改写用户已经保存的 `songs/` 文件。

## 使用

### 只找谱，不演奏

```bash
python songlib.py --list --refresh
python songlib.py --search 春日影
python songlib.py --search 父亲 --source shallow
python songlib.py --search 春日影 --source je
python songlib.py --search 小星星 --source visualizer --download
```

`--download` 只下载搜索结果中排名最高的可下载项，不发按键。结果仅有链接时返回非零状态，
不会把“给出了链接”伪装为下载成功。自定义目录：`-o "D:/我的曲谱"`。

### 搜索、下载并检查时间轴

```bash
python play.py --song-search 小星星 --source visualizer --dry-run --timing standard
```

移除 `--dry-run` 后才进入实际演奏流程；建议先检查时间轴再切到游戏测试。
`--song-search` 有多个可下载结果也不会询问编号；交互入口 `python play.py` 输入 `1` 才会询问。
只有已获得的**兼容、包含节奏的文本谱**适合 `--paste`；不要直接粘贴缺少时值的音高谱。

## 网络与缓存

- 并发检索不同来源，单源失败保留其他结果并显示警告。
- 所有选定来源都失败时明确报告网络/接口错误，而不是“没搜到”。
- 每个请求默认超时 12 秒，暂时性网络或服务器错误最多请求两次；客户端错误和限流不自动重试。
- shallow 的匿名令牌遇到 HTTP/业务码 401 只刷新一次；不读取或复用用户登录态。
- 目录按 ID 去重并核对 API `total`；重复页、空页截断、结构错误和分页超限不保存成完整缓存。
- 目录缓存 6 小时；联网失败最多回退 7 天内结构有效的旧缓存，并在命令行明确标注。
- `--refresh` 跳过新鲜缓存，失败时仍允许旧缓存回退，不能据旧缓存宣称接口当前在线。
- 缓存原子写入；缓存目录不可写不会令成功的在线结果失败。版本化目录缓存不会误用旧版数据。
- GitHub 匿名接口可能限流，不要求用户配置密钥，也不自动绕过限制。
- `visualizer` 正文按 Git blob 内容 SHA 校验，再转换为 `.jianpu`；音高与时值往返不符就不保存。
- 同名不同谱面、速度、调号或拍号另存为 `曲名(曲库).jianpu`，只有显式 `--force` 才覆盖原文件。

## 接口维护入口

实现集中在 `songlib.py`，不需要配置第三方付费搜索服务：

- shallow：`POST https://delta-test-api.shallow.ink/api/v1/auth/anonymous-token`，随机本机设备标识；
  `GET /api/v1/df/harmonica/songs?page=&pageSize=`，请求头 `X-Anonymous-Token`。
- visualizer：GitHub `git/trees/main?recursive=1` 枚举 `songs/` 文本文件，
  `git/blobs/<sha>` 按需读取正文；若上游改分支或路径，在该适配器维护，不修改播放逻辑。
- JE：GitHub `search/issues`，限定仓库、issue 和标题关键词；不批量枚举或下载 issue 正文。

`jiko_lib.py` 目前仅保留历史命名的匹配/安全命名/非覆盖保存兼容工具，以及本地 JSON 解析；
不再包含在线获取 jiko 曲库的实现。

## 可重复验收

```bash
# 纯离线测试：合成元数据和曲谱，不发按键
python -m unittest discover -s dev -p "test_*.py" -v

# 现有本地曲谱端到端回归，不发按键
python dev/selftest3.py

# 实际联网；临时下载谱面在测试完成后自动删除，不往 songs/ 添加文件
python dev/check_song_sources.py --refresh --downloads
```

联网验收只保存来源、计数、Git SHA 和解析结果摘要到 `_cache/source_check.json`，不保存令牌或曲谱正文。
网络不稳定、来源变化或限流可能使联网验收失败；离线 CI 不把第三方服务可用性当作代码通过条件。

### 本次实际验证（2026-10-20）

- shallow 完整分页：1058 个唯一曲目 ID。
- visualizer 文件索引：8 首；8 首均通过真实下载、Git 内容校验、音高/时值往返与可演奏按键表生成。
- JE：“春日影”返回原谱 issue 链接，标为待补节奏、不可自动下载演奏。
- 新增离线回归测试覆盖占位拒绝、分页、业务错误、缓存损坏与回退、匿名令牌更新、下载校验、
  非覆盖保存及非交互不提示等。
- 已有本地曲谱的解析、时间轴、导出与不变量校验通过。
- 未进行本次更新后的真实游戏按键演奏验证；`--dry-run` 不等于实机听感验收。

以上是当次实测，不代表上游数量或长期可用性保证；实时状态用验收命令重查。

## 未在本轮自动接入的候选

PiaStudy 的公开 MIDI 详情、SkyAutoMusic 的光遇 JSON、The Session 的 ABC/JSON 都发现了可读取数据，
但分别需要可靠的主旋律选择、光遇音高/复音/时值转换、ABC 解析支持。它们不等同于当前可直接演奏的口琴谱，
因此本轮不以网址数量充当功能完成，也不承诺未经实现的下载或格式转换。
